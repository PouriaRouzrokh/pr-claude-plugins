## Context

### Research findings that shaped the design (code.claude.com/docs, Oct 2026)

- `context: fork` runs the skill as a subagent prompt without the conversation history; forks can launch nested subagents (up to three levels) but cannot use `AskUserQuestion`. `background` defaults to true.
- Plan mode blocks writes to `.claude/` (a protected path); only plan files are exempt. `ExitPlanMode` presents the plan for approval.
- Task tools (TaskCreate, ...) and TodoWrite are enabled by default only on older models (Claude 3.x, Opus 4–4.7, Sonnet 4–4.6, Haiku 4.5), so skills cannot require them.
- `/code-review`, `/simplify`, `/security-review`, `/run`, `/batch` are built in. `isolation: worktree` gives an agent its own worktree; changes return only through its branch.
- Anthropic's prompting guidance for current models: dial back aggressive "CRITICAL/MUST" language and explain the reason instead; only add context Claude lacks.

### Key Files

- `pr/shared/checkpoint.py`, `pr/shared/checkpoint-system.md`, `pr/shared/rfd-template.md` — new single source of truth
- `pr/skills/{feature-dev,mvp-dev,clean-codebase,update-docs,create-snapshot,handle-claude-md,create-prd,atlas-development,commit-push,run-local,run-public}/SKILL.md` — rewritten

### Constraints

- `${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_SKILL_DIR}` are substituted in SKILL.md text only, so shared reference files refer to the helper by name.
- System Python on the user's Mac is 3.9, so the helper uses the standard library and 3.8+ syntax.

## Plan

### Chosen Approach

Centralize the documentation conventions and numbering in a helper script plus one conventions file and one RFD template; rewrite each workflow skill to call the helper and to use built-in Claude Code features where verified; delegate the frontend audits to three parallel agents, each owning a separate directory.

### Alternatives Considered

- A hidden "conventions" skill loaded via the Skill tool — rejected: an extra tool call per use, and model-invocation is less deterministic than reading a known path.
- Forking `update-docs` — rejected: it needs user approval mid-run, which forks cannot request.
- Entering plan mode automatically in `feature-dev` — rejected: plan mode blocks the RFD writes the workflow depends on; the skills use `AskUserQuestion` and switch to `ExitPlanMode` only when already in plan mode.
